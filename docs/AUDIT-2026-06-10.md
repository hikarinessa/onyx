## 1. Executive Summary

**Overall health: B.** Onyx is an unusually disciplined pre-1.0 codebase: strict TypeScript passes clean, SQL is fully parameterized, config writes are atomic, and `docs/DEBT.md` is a model of honest self-accounting. What pulls the grade down is not the code itself but the absence of *enforcement*: there is no CI of any kind, `npm run lint` currently fails with **379 errors**, the frontend has **zero tests**, and several acknowledged data-loss edge cases (external-edit overwrite, save-after-rename ghost files) have sat in the debt tracker unfixed while feature phases shipped. The top three risks are: (1) silent data loss in a note-taking app via the stale-editor-cache overwrite path, (2) regression risk from 2,000+ line god-files (Settings.tsx, commands.rs, livePreview.ts) with no test safety net, and (3) mutex-poisoning panics that can kill the watcher thread and silently stop indexing. The top three opportunities are: (1) a CI gate (lint + tsc + cargo test) is a half-day of work that locks in all existing quality, (2) the 27 existing Rust tests prove the team can write good tests — extending that to `reconcile()`, `validate_path`, and link-rewriting covers the riskiest logic cheaply, and (3) splitting `commands.rs` and `Settings.tsx` along their already-obvious seams would cut the cost of every future change. Documentation is a genuine strength, though CLAUDE.md's structure map has drifted from reality.

## 2. Repo Map

**Purpose:** Lightweight, offline-first markdown note-taking app (Obsidian-adjacent: wikilinks, periodic notes, typed objects, live preview). Single-user macOS-first desktop app, apparent maturity: late-stage personal project approaching 1.0, built largely with AI assistance (`.claude/`, CLAUDE.md, per-phase dev plan).

**Stack:** Tauri 2 (Rust backend) + React 19 + TypeScript 5.9 (strict) + CodeMirror 6 + SQLite (rusqlite, WAL) + Zustand. Plain CSS with `@layer` discipline, no Tailwind. Vite build; no test runner configured for the frontend; 27 Rust unit tests.

**Architecture sketch:** Three-owner state model — Zustand owns UI state (panes/tabs/panels), CM6 owns editor state (one `EditorView` per pane, `EditorState` cached per tab), Rust owns files + SQLite index. All file mutations are supposed to flow through `src/lib/fileOps.ts` → Tauri commands → `fs:change` events → central handler in `App.tsx`. Background indexer + debounced file watcher keep SQLite reconciled with disk.

**Key directories:**

| `src/components/` | React UI (Sidebar 910, Settings 2058, ContextPanel 938, Editor 705 lines) |
| `src/extensions/` | CM6 extensions (livePreview 1579, embeds 712, linting 441 lines) |

## 3. Audit Report

Severity scale calibrated to a single-user local desktop app. **[F]** = verified fact, **[J]** = judgment. Findings sorted by severity within each dimension.

### 3.1 Correctness & error handling

**C1 · HIGH [F] — External-edit overwrite: acknowledged data-loss path, still open.**
`docs/DEBT.md` ("External edit conflict detection", item #3): if a file is modified externally while open with unsaved changes, the stale editor cache can overwrite the external edit on next auto-save. For a notes app, silent data loss is the single worst failure class. The mtime-conflict check on `write_file` (commands.rs:269 area) mitigates but DEBT explicitly documents the surviving window. This has been open across multiple release phases.

**C2 · HIGH [F] — Auto-save fires at stale path after rename (ghost files).**
`docs/DEBT.md` citing `Editor.tsx:142`: the debounced save closure captures `tab.path` at edit time; rename within the 500 ms window recreates the file at the old path. Combined with C1, the save pipeline has two known integrity holes.

**C3 · HIGH [F] — Mutex `.unwrap()` can poison-panic background threads.**
`watcher.rs:73, 109, 172, 205`, `lib.rs:220` (*reported; pattern confirmed by grep — 46 `.unwrap()` total in Rust*). `indexer.rs::reconcile()` handles a poisoned DB mutex gracefully (~line 65), but the watcher paths don't. A panic while holding the DB lock kills file-change detection for the rest of the session with no user-visible symptom — notes silently stop being indexed.

**C4 · MEDIUM [F] — 12 empty `.catch(() => {})` swallow IPC failures; no notification system.**
Verified count: 12, e.g. `App.tsx:240, 458, 561, 602, 608`. Config saves (`invoke("update_config")`) failing silently means settings changes that never persist with zero feedback. Root cause is the absence of any toast/notification primitive — DEBT items #12 and others all block on it.

**C5 · MEDIUM [F] — Architecture rule violated: direct `invoke("write_file")` outside fileOps.ts.**
`App.tsx:402` (block-extract-to-note). CLAUDE.md and GUIDELINES mandate all mutations flow through `fileOps.ts`; this bypass skips cache/tab synchronization, exactly the desync class the rule exists to prevent.

**C6 · MEDIUM [F] — Known open bugs in file-op edge cases.**
From DEBT.md, all still open: `unregister_directory` doesn't stop the watcher (commands.rs:258 — orphan reindexing pollutes search), orphan rename fails validation (commands.rs:493), `update_frontmatter` can produce double frontmatter blocks on malformed files (#24).

**C7 · LOW [J] — All Rust errors are `Result<_, String>`.**
Pervasive (every command in commands.rs). Adequate for a desktop app, but stringly-typed errors make it impossible for the frontend to distinguish "conflict" from "denied" except by prefix-sniffing (`CONFLICT:` is already doing this — a typed error enum serialized via serde would be cleaner).

### 3.2 Security

Context: local single-user app, strict CSP, no network features. The realistic threat is a webview compromise (malicious note content exploiting CM6/WebKit) escalating through IPC.

**S1 · MEDIUM [F] — `allow_path` is a blocklist, not an allowlist.**
`commands.rs:1333–1360` (verified). Blocks `/etc`, `/usr`, … and 5 home dirs (`.ssh`, `.gnupg`, `.aws`, `.config/gcloud`, `.kube`), but everything else in `$HOME` — `~/.netrc`, `~/.npmrc`, browser profiles, `~/Library/Keychains` (under blocked `/Library`? no: that's user-`~/Library`, not blocked) — can be allowlisted by the frontend and then read/written via `read_file`/`write_file`. Acceptable for the product's design (users open arbitrary orphan notes), but the blocklist gives a false sense of coverage. Consider requiring a native dialog handle for out-of-vault paths, or at minimum extending the blocklist (`~/Library`, `~/.netrc`, `.env*`).

**S2 · MEDIUM [F] — Templates can execute arbitrary user scripts.**
`periodic.rs:271–307` registers a `script(name, ...)` minijinja function; `scripts.rs:100+` spawns executables from `~/.onyx/scripts/` (inheriting the full parent environment — `.envs()` adds, doesn't replace). Folder rules also trigger scripts on file creation (`commands.rs:1631`). By design and the timeout correctly kills the child (`scripts.rs:142–148`, verified), but: opening a periodic note = code execution. This deserves explicit documentation and ideally a first-run confirmation per script. Not in ARCHITECTURE.md at all.

**S3 · LOW [F] — Wikilink/regex processing has no input size guard.**
`indexer.rs` iterates `captures_iter` over arbitrarily long lines (*reported*). A pathological multi-MB single-line file degrades the indexer. Cheap guard: skip lines > 1 MB.

Otherwise healthy: CSP is tight (`default-src 'self'`; `unsafe-inline` only for styles, required by CM6) — tauri.conf.json:25; capabilities are minimal (window controls + fs/dialog/opener defaults); all SQL parameterized (`params![]` throughout db.rs); no secrets in repo; atomic temp+rename writes for config (commands.rs:26–73).

### 3.3 Testing

**T1 · HIGH [F] — Zero frontend tests, no test runner installed.**
`find src -name "*.test.*"` → 0; no vitest/jest in package.json. The most intricate, regression-prone code in the repo — livePreview.ts (1,579 lines of decoration logic with documented crash history, see CHANGELOG `1c8479a`, `7718421`), fileOps tab lifecycle, pane store, session restore — has no safety net. Phase 11 keeps adding to exactly these files.

**T2 · HIGH [F] — Rust tests are good but miss the riskiest modules.**
27 `#[test]`s confined to periodic.rs (14, template/date logic), indexer.rs (5, extraction), commands.rs (8, link rewriting). They assert real behavior — quality is fine. Untested: `db.rs` entirely (reconciliation queries, `rename_dir_prefix` with its known UTF-8 byte/char bug, DEBT #15), `reconcile()`, watcher debounce, `validate_path`/`allow_path` (the security boundary), conflict detection.

**T3 · HIGH [F] — No CI.** No `.github/`, no hooks. Nothing runs `cargo test`, `tsc`, or eslint automatically; the broken lint (Q1) proves the consequence.

### 3.4 Code quality

**Q1 · HIGH [F] — `npm run lint` fails: 379 errors.**
Verified run. Dominated by `react-refresh/only-export-components` (~133), `react-hooks/set-state-in-effect` (~60 — these are real smell-class warnings worth triaging, not just noise), `no-useless-escape` (~36, e.g. livePreview.ts:678, wikilinks.ts:31), `no-unused-vars` (~12), a few `no-explicit-any` (tags.ts:94). A lint config that's never enforced is worse than none — it trains contributors to ignore it.

**Q2 · MEDIUM [F] — God files, still growing.**
Settings.tsx 2,058 · commands.rs 1,732 · livePreview.ts 1,579 · ContextPanel.tsx 938 · App.tsx 941 · layout.css 4,198. Each has grown 20–30% past the sizes recorded in CLAUDE.md. commands.rs alone hosts ~10 unrelated domains (file ops, search, bookmarks, frontmatter, periodic, scripts, folder rules, config, spellcheck, session). **[J]** None is unmanageable yet, but every one is a merge-conflict and regression hotspot, and livePreview.ts has the crash history to show for it.

**Q3 · MEDIUM [F] — Zustand compat getters: known-broken API left loaded.**
`stores/app.ts` still exports `store.tabs`/`store.activeTabId` getters that freeze after the first `set()` (documented in CLAUDE.md, bug #61 already happened). All current callers are migrated, but the footgun remains chambered for every future contributor. **Q4 · LOW [F] — Duplicated wikilink regexes/click logic across extensions.**

**Q5 · LOW [F] — Type safety is genuinely good.** Zero `as any` casts in src/ (verified); strict tsconfig; `tsc --noEmit` clean. Residual holes are untyped `invoke<T>` payloads trusted implicitly.

### 3.5 Performance

**P1 · MEDIUM [F] — `search_content` is a synchronous full-vault disk walk per keystroke-search.**
commands.rs ~415–500; acknowledged in DEBT. Reads every `.md` on each search, on the command thread. Fine <1k files; the fix (SQLite FTS5, which also fixes P2) is well-understood.

**P2 · MEDIUM [F] — `LIKE '%…%'` queries bypass indexes.**
db.rs:313 (search_files), db.rs:405 (resolve_by_title path fallback) (*reported*). Full table scans; `query_by_type`'s `json_extract` scan is acknowledged (DEBT #13). All converge on the same answer: FTS5 + a couple of targeted indexes before advertising large-vault support.

**P3 · LOW [F] — Frontend caches are mostly disciplined.**
`editorStateCache`/`scrollCache`/`lastSavedContent` are cleaned against open tabs (Editor.tsx:587–600 cleanup verified by agent); ipcCache is TTL-only but tiny; Rust mtime map is capped at 500 with half-eviction (commands.rs:239–269, verified — an earlier-generation concern already fixed). No action needed beyond a max-size on ipcCache.

The same functionality is partly available via the already-imported `@cloudworxx/tauri-plugin-mac-rounded-corners` — worth consolidating.

**D3 · LOW [F/J] — Lockfile hygiene + niche deps.**

### 3.9 Strengths (preserve these)

1. **Atomic writes everywhere** — temp + rename for config/session/bookmarks (commands.rs:26–73, dirs.rs excepted per DEBT).
2. **Parameterized SQL throughout** db.rs; zero injection surface.
3. **Startup reconciliation** (indexer.rs:24–141): disk-vs-DB diff handling adds/deletes/renames, ordered to avoid races.
4. **Watcher self-write suppression** (watcher.rs:233 + commands.rs) preventing index feedback loops.
5. **Centralized mutation layer** (`fileOps.ts`) + central `fs:change` handler with rename/delete buffering (App.tsx:614–658) — the right architecture, 95% adhered to.
6. **Debt culture**: DEBT.md tracks ~40 items with file:line precision and honest severity calls; CLAUDE.md gotchas encode real CM6/Tauri/Zustand landmines.
7. **Strict TS with zero `as any`** and clean `tsc` on a 14k-line frontend.

## 4. Improvement Strategy

Four themes explain nearly all findings:

**Theme 1 — Quality exists but nothing enforces it.** (T3, Q1, X1, D3, DOC1)
The repo has eslint, strict tsc, 27 good tests, and meticulous docs — and no mechanism that runs any of them. Entropy is winning exactly where automation is absent: lint rotted to 379 errors, CLAUDE.md drifted, the lockfile froze at 0.10.3.
*Target state:* a CI workflow (and optionally a pre-commit hook) that runs `tsc --noEmit`, `eslint --max-warnings 0`, `cargo check`, `cargo test` on every push; lint debt paid down to zero first.
*Principle:* a check that doesn't run automatically doesn't exist.

**Theme 2 — The save pipeline is the product; it still has known integrity holes.** (C1, C2, C4, C6)
Everything else in a notes app is negotiable; "my note didn't get destroyed" is not. The two data-loss windows are documented, understood, and unfixed.
*Target state:* external-edit conflict produces a visible prompt, never an overwrite; renames flush or retarget pending saves; IPC failures surface in a toast primitive that all `.catch(() => {})` sites adopt.
*Principle:* user data failures must be loud.

**Theme 3 — Complexity is pooling in five files with no test net under them.** (Q2, T1, T2, C3)
livePreview.ts's own changelog shows the pattern: crash, fix, crash differently. The cost of every Phase 11+ feature is rising.
*Target state:* vitest harness with focused tests on the highest-churn pure logic (decoration builders, fileOps, panes store, session); commands.rs split into domain modules; Rust tests on db.rs + path validation. Coverage target: the *core* (fileOps, stores, db, indexer) ≥ 70%, not the whole repo.
*Principle:* test the 20% that breaks; split files along the seams they already have.

**Theme 4 — Capability outgrew the documented security model.** (S1, S2, DOC2)
Script execution and a blocklist-based path gate accumulated without a stated threat model.
*Target state:* one page in ARCHITECTURE.md stating the model (webview-compromise escalation is in scope or not), `allow_path` hardened or justified, scripts documented with a first-run consent gate.
*Principle:* decide the threat model explicitly; then the code is either right or wrong against it.

**Recommended NOT to fix now** (effort > payoff at this maturity):
- FTS5 / search performance (P1, P2) — current vault sizes don't hurt; do it when targeting other users or >5k-file vaults.
- `Result<_, String>` → typed errors (C7) — large diff, modest payoff; fold into commands.rs split opportunistically.
- objc2 migration (D1) — wait for actual breakage or a Tauri-ecosystem replacement; isolate, don't rewrite.
- Accessibility backlog (DEBT UI items) — important for release-to-public, not for the current single-user reality.
- layout.css decomposition — 4k lines of CSS is ugly but cheap to live with given `@layer` discipline.

**"Done" signals:** CI green is required to merge; `npm run lint` exits 0; zero empty `catch` blocks (enforced by a lint rule); a forced external-edit conflict in manual testing shows a prompt and loses nothing; `cargo test` covers reconcile + validate_path + rename-rewrite; no file > 1,200 lines except layout.css; CLAUDE.md regenerated and spot-accurate.

### Implementation sketches — top 3

**0.1 CI workflow.** One job, macOS runner not required for check/test (use ubuntu + `--no-default-features`? No — Tauri needs system deps; simplest reliable: `macos-latest`, cache cargo + npm). Steps: checkout → setup node 20 + `npm ci` → `npx tsc --noEmit` → `npx eslint . --max-warnings 0` (add after 0.2; until then run non-blocking) → rust-toolchain + `cargo check && cargo test` in `src-tauri`. Gotchas: `cargo test` needs no display; keep `tauri-build` out of test path (it's build-dep only, fine); cache `~/.cargo` and `src-tauri/target` keyed on Cargo.lock or CI minutes will hurt.

**1.3 External-edit conflict guard.** Approach: in App.tsx's `fs:change` modify-branch, when `path` matches an open tab: if tab is clean → current behavior (`replaceTabContent`). If dirty → read disk content; if disk == `lastSavedContent` it's our own echo (self-write suppression should already filter — verify DEBT's open question here first); if different → set `saveConflictPath` (mechanism already exists in StatusBar for the mtime path) and **suspend autosave for that tab** until resolved (keep newest in editor, offer "reload disk version" / "keep mine (overwrite)" via 1.1 toast-with-actions). Key steps: (1) add `suspendAutosave` set keyed by tab id checked in the Editor debounce; (2) wire prompt; (3) vitest the decision matrix (clean/dirty × echo/external). Gotchas: the watcher self-write suppression may be leaky (DEBT explicitly flags it unverified) — instrument first; don't compare via mtime (the map clears at 500 entries), compare content hashes; rapid-rename + modify ordering (the 300 ms remove buffer) can deliver modify-before-rename — handle path-miss gracefully.

**2.1 commands.rs split.** Approach: pure mechanical relocation. (1) Create `src-tauri/src/commands/mod.rs` re-exporting everything to keep `lib.rs`'s `generate_handler!` list compiling unchanged; (2) move functions in domain batches (files → search → bookmarks → …), `cargo check` between batches (kill `cargo tauri dev` first, per CLAUDE.md gotcha); (3) shared helpers (`canonical_path`, `validate_path`, mtime map access) go to `commands/guard.rs` — this also creates the natural home for 0.4's tests; (4) leave `#[tauri::command]` attributes untouched. Gotchas: `generate_handler!` requires the exact path used in registration — re-exports avoid touching it; keep the `AppState` definition out of the module to dodge cycles; do it in one sitting to avoid long-lived branch conflict with Phase 11 work.
